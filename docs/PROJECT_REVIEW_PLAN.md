## GUI 与工程层面的检查结果（检查前基线）

- **任务结果与材料状态可能混用**：运行仿真只禁用运行按钮，材料选择仍可改变 `self.model`、`self.preset` 与工程树；`_on_results()` 使用这些可变对象解释旧 worker 的结果。需绑定任务快照，并拒绝过期结果。
- **线程关闭缺少完整约束**：BandViz 重载文件调用 `terminate()`，关闭窗口不处理 worker；vdW Studio 等待 2 秒后直接接受关闭，未处理尚未结束的线程。Qt 明确说明强制终止可能中断数据修改，销毁仍运行的 QThread 可导致崩溃。依据：[Qt QThread 官方文档](https://doc.qt.io/archives/qt-5.15/qthread.html#terminate)。这些风险尚未通过长任务关闭场景动态复现。
- **重计算仍进入主线程**：BandViz 参数修改时同步计算完整 DOS（`gui/main_window.py:294`）；vdW Studio 的谷物理网格计算在 `_on_results()` 内执行（`:359`）。初次后台计算不等于全部交互都保持响应。
- **依赖与支持版本矛盾**：README 宣称 Python 3.9+；固定 NumPy/SciPy 的本机包元数据要求 Python ≥3.12，Matplotlib 要求 ≥3.11；CI 的 Python 3.10/3.12 矩阵安装未固定依赖，未验证 `requirements.txt` 所定义的环境。
- **交付信息不完整**：缺少 `pyproject.toml`、实际 LICENSE 文件；CLI 文档含未实现的 `--emin/--emax`。Phase 2 的部分应变/双层电场与 Phase 6 的数据库/筛选示例已存在，但 ROADMAP 状态未同步。
- **批处理资源与复现信息**：CLI 创建多幅图后未关闭；结果记录缺少代码版本、完整求解参数、输入校验摘要和数值收敛信息。默认结果目录和数据库的忽略规则不完整，现有 `screening.db` 已是未跟踪文件。
- **模型验证等级需要区分**：SK 带隙尚未匹配文献；BM 有限 k 处 C₃ 误差是 ROADMAP 已记录的限制。`moire.py` 文件头写 T₁/T₃/T₂，`_build_coupling()` 写并使用 T₁/T₂/T₃，注释约定内部矛盾。不能仅以魔角或单个带边匹配证明全域可靠。
